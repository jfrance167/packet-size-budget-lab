# Security scope

This is a fictional byte-count arithmetic model, not packet/transport validation,
path discovery or operational configuration advice. Counts/options/extras are analyst
assertions, not measured headers. Only invented data in scope; no real operational
records, targets, addresses, payloads or captures. No dependencies/traffic/probes,
system changes, fragment generation/reassembly or publication authorized.

Threats include hostile JSON resource costs, misleading labels, duplicate/unknown
fields, numeric coercion and invalid late cases hidden by early unsupported/over-budget
outcomes. API requires exact built-in bytes; whole strict finite admission precedes
all rows, with duplicate-key and bounded type/depth/string/number/container checks.
Length-domain confusion and double-charged extras are correctness hazards tested
against pre-code independently calculated fixtures and literal field ceilings.

Reports expose full supplied fictional assumptions. Outer fields, option contents,
actual delivery/path MTU/link minimum compliance remain unverified even when fit
is true. No negotiated TCP MSS or full standards-conformance claim. Logic limits
workload/output, not hard CPU/RSS containment or guaranteed downstream safety.
Delivery can leave partial output on failure; error status remains 2.

Tests/verifier run fixed installed Python with owned scripts and synthetic inputs;
the application contains no network/process capability. Capability mocks and Bandit
are scoped evidence, not isolation/security certification. Report suspected defects
with a small invented scenario and expected/actual ledger, never private data.
No external disclosure destination configured.
